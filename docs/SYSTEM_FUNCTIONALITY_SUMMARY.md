## 0. 全局概览

### 系统是什么

千万字全本地离线有声书生成流水线。用户把小说文本丢进来，系统自动解析为多角色剧本，合成为语音，混音导出成品 MP3。所有 AI 推理在本机 GPU 上跑（LLM 用 Qwen，TTS 用 IndexTTS-2.5），不依赖外网。

### 用户是谁

个人自用。几十本小说、每本几十到几百章。本机操作，不需要移动端适配。

### 技术约束（重构不能改变的）

- **离线优先**：vendor 文件必须本地化，不能用 CDN
- **无构建工具**：不能引入 npm/webpack/vite，保持纯 `<script>` 标签加载
- **GPU 互斥**：LLM 和 TTS 不能同时运行（共享显存），界面需让用户感知 GPU 当前归属
- **后端 API 已定型**：FastAPI REST + SSE，前端只能消费这些端点，不能改后端

## 1. 全局框架（所有页面共享）

### 1.1 顶栏

```
┌──────────────────────────────────────────────────────────────────┐
│ novel2audiobook    [小说] [角色库] [设置]                          │
│ CPU 23%  内存 12.4/31.3G  GPU 87%  显存 18.2/24.0G  🔵TTS 占用   │
└──────────────────────────────────────────────────────────────────┘
```

**左侧**：应用名 + 三个导航 Tab（小说 / 角色库 / 设置），Tab 高亮当前页。

**右侧资源监控条**（实时刷新）：
- CPU 百分比
- 内存用量（已用/总量，MB 或 G 自动切换）
- GPU 占用百分比
- 显存用量
- GPU 归属指示器：🟢LLM 占用 / 🔵TTS 占用 / ⚪空闲

数据来源：SSE `resource` 事件每秒推送。SSE 连续 3 次报错后断开，降级为 3 秒轮询 `GET /api/monitor`，同时顶栏显示红色「实时连接已断开」标签。

### 1.2 路由与页面记忆

Hash 路由，5 条：

| Hash | 页面 |
|---|---|
| `#/novels` | 小说列表（默认首页） |
| `#/novels/:nid` | 小说详情 |
| `#/novels/:nid/chapters/:cid` | 配音工作台 |
| `#/roles` | 全局角色库 |
| `#/settings` | 系统配置 |

每次路由变化写 `localStorage['n2a.lastRoute']`。启动时如果 URL 没 hash，恢复上次页面（记录的小说/章节已不存在则回落到 `#/novels`）。

### 1.3 通用组件

- **Toast 通知**：右上角弹出，3 秒自动消失。成功（绿）/ 错误（红）/ 警告（橙）。
- **确认弹窗**：所有二次确认都走它。支持显示「影响面说明」文本（删除节点、重新导入正文、批量覆盖预检都要用）。
- **所有 API 报错都弹 toast**，不静默吞掉。

## 3. 小说详情页（`#/novels/:nid`）

这是最复杂的页面。三区域布局：左侧树形目录 | 右侧详情面板 | 底部任务面板。

```
┌────────────────┬────────────────────────────────┐
│ 树形目录        │ 详情面板                         │
│                │                                │
│ [刷新]         │ 选中节点标题 / 统计信息           │
│ + 新增部       │ 批量任务按钮                     │
│ + 新增卷       │ 章节操作 / 节点操作              │
│ + 新增章节     │                                │
│                │                                │
│ ● 第一卷       │                                │
│   ├ ch_0001   │                                │
│   └ ch_0002   │                                │
│ ● 第二卷       │                                │
│   └ ch_0003   │                                │
├────────────────┴────────────────────────────────┤
│ ▼ 任务队列 (3)                                   │
│   批量 TTS · 第一卷 · 2/3 章完成                  │
│     ch_0001  已完成                              │
│     ch_0002  运行中  [取消]                       │
│     ch_0003  排队中  [取消]                       │
└─────────────────────────────────────────────────┘
```

### 3.1 左侧树形目录

**数据来源**：一次 `GET /api/novels/:nid/tree` 拿回整棵树 + 每章状态。

**节点类型**：
- **部（part）**：可包含卷或章
- **卷（volume）**：只包含章
- **章（chapter）**：叶子节点，没有 children

**每个节点显示**：
- 状态色点：灰(未解析) / 蓝(已解析) / 绿(已配音) / 黄(陈旧)
- 节点标题
- 右侧操作按钮（hover 时显现）：✏️ 重命名 / 🗑️ 删除

**节点 checkbox**：章节节点可多选，用于批量任务范围选择。

**拖拽排序**：用 SortableJS 实现。支持跨层级拖动（比如把一个章节从卷 A 拖到卷 B）。拖完调 `POST /nodes/reorder`，失败时 UI 回滚到原顺序并弹错误提示。

**新增按钮**：「+ 新增部」「+ 新增卷」「+ 新增章节」，分别弹 `prompt()` 输入名称。

**删除**：二次确认（「确定要删除「XXX」吗？」）。

**重命名**：`prompt()` 输入新名称。

### 3.2 右侧详情面板

根据选中节点类型动态切换内容：

#### 选中章节时

**统计条**：
```
总分块 121  |  已配音 87  |  未配音 34  |  未绑定角色 6
```
未绑定角色数 > 0 时数字标红。

**章节操作区**：
- 「进入配音工作台」按钮 → 跳转 `#/novels/:nid/chapters/:cid`
- 「重新导入章节文本」按钮 → 上传 .txt/.md 文件

**重新导入流程**（两步确认）：
1. 选文件后，先调不带 confirm 的 `PUT .../raw` 获取影响面
2. 弹窗显示：「将清空：script_draft.json、script_final.json、timeline.json。已合成的 N 个语音片段会保留在缓存里。此操作不可撤销。」
3. 用户确认后带 `?confirm=1` 再调一次

#### 选中部/卷时

**节点操作区**：
- 「+ 新增卷」/「+ 新增章节」按钮（根据父节点类型）
- 「上传章节」按钮 → 先 `prompt()` 输入章节名，再选文件

#### 未选中任何节点时

居中图标 +「选择左侧节点查看详情」。

### 3.3 批量任务区域

**常驻显示**在详情面板顶部，不依赖选中具体节点。

**范围提示**：
- 如果有多选章节 →「已选中 N 个章节」
- 如果只选了一个节点 →「章/部/卷《XXX》」
- 什么都没选 →「整本小说」

**三个按钮**：「批量解析」「批量生成人声」「批量混音导出」

**每个动作的固定两步流程**：
1. 先调 `POST /api/tasks/preflight` 获取汇总
2. 弹窗显示：
   ```
   本次涉及 12 章：新生成 8 章，3 章已有成品将被重新生成，1 章无需处理。
   预计 GPU 耗时：约 95 分钟。
   ```
   （`estimated_gpu_minutes` 为 null 时显示「未知（尚无历史数据）」，不编数字）
3. 用户确认后调 `POST /api/tasks` 提交

### 3.4 底部任务队列面板

固定在页面底部，可折叠。

**任务按 group_id 聚合**：
```
▼ 任务队列 (3)
  ┌─ 批量 TTS · 第一卷 · 2/3 章完成 ─── [取消] ─┐
  │ ch_0001  已完成                               │
  │ ch_0002  运行中  [取消]                       │
  │ ch_0003  排队中  [取消]                       │
  └──────────────────────────────────────────────┘
```

- 每个 group 可展开/收起
- 展开后可点任务行看日志（`GET /api/tasks/:id/log?offset=` 增量拉取，只在展开时拉）
- 运行中/排队中的任务有取消按钮（`DELETE /api/tasks/:id`）
- 数据来自 SSE `task_update` 事件

┌──────────────────────┬──────────────────────────┐

│                      │                          │
│ 总分块 121 | 已配音 87│ 原文文本                  │
│ 未配音 34 | 未绑定 6  │ ┌──────────────────────┐ │
│                      │ │ 当那一天终于来临时...  │ │
│ [全选未绑定]          │ │                      │ │
│ [返回小说详情]        │ └──────────────────────┘ │
│                      │                          │
│ ☐ 1  那一天终于来临... │ 角色绑定                 │
│ ☐ 2  "你来了。"柳禾.. │ [柳禾            ▼]     │
│ ☐ 3  我走上前去...    │                          │
│ ☐ 4  "我知道你会来..  │ 语气标签                 │
│    ...               │ [悲伤              ▼]     │
│                      │                          │
│ ┌─已选择 3 个分块───┐ │ 试听                     │
│ │ [绑定][语气][清空] │ │ [仅人声] [混音预览]      │
│ │ [批量生成人声]     │ │ ▶ ──────── 0:03        │
│ └───────────────────┘ │                          │
│                      │ 操作                     │
│                      │ [重新生成本块人声]         │
│                      │                          │
│                      │        [取消]  [保存]     │
└──────────────────────┴──────────────────────────┘

### 4.1 左侧分块列表

**顶部统计条**：
```
总分块 121  |  已配音 87  |  未配音 34  |  未绑定角色 6
```
未绑定角色数 > 0 时数字标红。

**「全选未绑定」按钮**：一键选中所有 speaker 为空的分块。

**分块卡片列表**（虚拟滚动）：
- 固定行高 88px，只渲染可视区域附近卡片（长章节 500+ 分块不卡）
- 每张卡片显示：
  - seg_id（等宽字体，如 `5`）
  - 文本前 40 字 + `...`
  - 绑定角色名（灰色），未绑定时显示「⚠ 未绑定」（红色加粗）
  - 状态点（绿=已合成，灰=未合成）
- **speaker 为空的卡片整张标红**（红色边框 + 浅红背景）
- 点击卡片 → 右侧编辑面板加载该分块
- 支持 checkbox 多选（点击卡片左侧 checkbox 区域）

**底部批量操作栏**（选中分块时出现，sticky 定位）：
```
已选择 3 个分块                    [绑定角色] [修改语气] [清空角色] [批量生成人声]
```

**批量操作交互**：
- 「批量绑定角色」→ `prompt()` 输入角色名 → 按名字查找角色 → 调 `POST .../segments/batch`
- 「批量修改语气」→ `prompt()` 输入语气标签 → 调 `POST .../segments/batch`
- 「批量清空角色」→ 二次确认 → 调 `POST .../segments/batch`（speaker 设为 null）
- 「批量生成人声」→ **前端先拦截**：选中分块里有未绑定角色的直接报错「选中的分块中有 N 个未绑定角色，请先指派」→ 通过后调 preflight → 弹窗确认 → 提交任务

### 4.2 右侧单块编辑面板

**未选中分块时**：居中图标 +「选择左侧分块进行编辑」。

**选中分块后**，从上到下依次是：

#### 原文文本
```
原文文本
┌──────────────────────────────┐
│ 那一天终于来临时，我站在城门  │
│ 外，看着远方升起的狼烟...     │
└──────────────────────────────┘
```
textarea，可直接编辑。

#### 角色绑定
```
角色绑定
[柳禾            ▼]
```
自定义下拉（不是原生 select）：
- 列出所有角色（从 `GET /api/roles` 获取）
- 点击角色 → 绑定到当前分块（存角色 id，不是显示名）
- 底部有分割线 +「+ 新建角色并绑定」入口
  - 点了弹 `prompt()` 输入角色名 → 调 `POST /api/roles` 创建 → 自动绑定到当前分块 → 刷新角色列表
  - **这是补齐缺失角色的唯一路径**，parse 不再自动注册角色

#### 语气标签
```
语气标签
[悲伤 ▼]
```
原生 `<select>` 下拉，8 个选项：
- 中性(neutral) / 开心(happy) / 生气(angry) / 悲伤(sad)
- 严肃(serious) / 害怕(afraid) / 惊讶(surprised) / 平静(calm)

#### 试听
```
试听
[仅人声] [混音预览]
▶ ────────── 0:03
```

- **「仅人声」**：直接用浏览器 `<audio>` 播放 `GET /api/.../segments/:seg_id/audio`，不经过后端合成。该分块还没合成过时，点击后播放器会报错（没有"尚未生成"的置灰提示，这是当前的一个 UI 缺陷）。
- **「混音预览」**：播放 `GET /api/.../output.mp3`（整个章节的混音成品）。如果还没混过音，播放会失败。

#### 操作
```
操作
[重新生成本块人声]
```
点击后二次确认（「会对整章重新跑一次增量 TTS（其余已合成且未改动的分块会命中缓存，不会重新生成）。确定继续吗？」）→ 实际提交的是整章级别的 TTS 任务（不是单块粒度）。

#### 底部按钮
```
[取消]  [保存]
```
- 保存：调 `PATCH /api/.../segments/:seg_id`，传 text/speaker/emotion
- 注意：文本改动会让该块的 md5 变化，原来的语音作废——当前 UI 没有提示这一点

### 布局

```
┌─────────────────────────────────────────────────┐
│ 全局角色库                     [+ 新增角色]       │
├─────────────────────────────────────────────────┤
│ [主角] [配角] [路人] [全部]     [管理分类]        │
├─────────────────────────────────────────────────┤
│ ┌───────────────────────────────────────────┐   │
│ │ 柳禾                                      │   │
│ │ 主角 · 女                                  │   │
│ │ ▶ reference.wav                           │   │
│ │ ✓ Embedding 有效  被 2 本小说、87 个分块引用│   │

│ │ 旁白                                      │   │
│ │ 未分类 · 未知                              │   │

### 分类筛选栏

- 标签列表：自定义分类（从 `GET /api/role-categories` 获取）+ 角色实际在用但没登记的分类 + 「全部」标签
- 点标签过滤角色列表
- 「管理分类」按钮 → 弹窗增删分类

### 管理分类弹窗

```
┌──────────────────────────────┐
│ 管理角色分类               × │
├──────────────────────────────┤
│ [新分类名称________] [添加]  │
│                              │
│ 主角                    [删除]│

│ 路人                    [删除]│
├──────────────────────────────┤
│                      [完成]  │
└──────────────────────────────┘
```

### 角色卡片

每张卡片显示：
- **角色名**（粗体）
- **分类 · 性别**（灰色小字）
- **参考音频播放器**：`<audio>` 标签内嵌，可直接播放（如有 reference.wav）
- **Embedding 状态徽章**：
  - ✓ Embedding 有效（绿底）
  - ⚪ 尚未预计算（灰底）
  - ✗ Embedding 已过期（红底）
- **引用统计**：「被 X 本小说、Y 个分块引用」
- **操作按钮**：[编辑] / [删除]
  - narrator 角色删除按钮置灰不可点
  - 删除时弹窗必须显示引用数量（「该角色被 87 个分块引用，删除后这些分块会变成未绑定」）

### 新增/编辑弹窗

```
┌──────────────────────────────┐

## 7. UI 交互细节与数据流总结

### 7.1 关键交互流程

#### 「未绑定角色」完整闭环（核心生产流程）

1. 解析一章 → 工作台里看到红色高亮的未绑定分块，顶部统计数字正确
2. 选中这些分块直接点「批量生成人声」→ **被前端拦住**并给出明确提示
3. 用下拉框里的「+ 新建角色并绑定」建一个新角色 → 分块变绿
4. 全部补齐后批量生成人声成功

#### 批量任务全流程

1. 选整卷 → 点批量 TTS → 看到预检汇总弹窗 → 确认
2. 底部任务面板出现 group 行 → 进度实时走动（SSE 推送）
3. 展开看日志 → 取消其中一个 → 状态变 cancelled

#### 树形拖拽

1. 拖动章节改变顺序 → 调 `POST /nodes/reorder`
2. 刷新页面顺序保持
3. 后端停掉再拖 → UI 回滚到原顺序并弹错误提示

### 7.2 SSE 事件驱动

| 事件类型 | 触发 UI 更新 |
|---|---|
| `resource` | 顶栏资源监控条数字刷新 |
| `task_update` | 任务面板重新拉取任务列表 |
| `tree_update` | 当前页面重新拉取树（如果在小说详情页） |

### 7.3 所有弹窗/输入方式一览

| 当前实现 | 位置 | 建议重构为 |
|---|---|---|
| `prompt()` | 新增小说/部/卷/章名称 | 自定义 modal + input |
| `prompt()` | 重命名节点 | 自定义 modal + input |
| `prompt()` | 批量绑定角色（输入角色名） | 下拉选择 |
| `prompt()` | 批量修改语气（输入标签） | 下拉选择 |
| `prompt()` | 新建角色并绑定（输入名称） | 自定义 modal |
| `confirm()` | 删除小说/节点/角色 | 自定义 confirm-dialog |
| `confirm()` | 重新导入章节 | 自定义 confirm-dialog（带影响面说明） |
| `alert()` | 批量生成人声拦截（未绑定角色） | toast 或 inline 提示 |
| `alert()` | 配置保存结果 | toast |
| 原生 `<select>` | 语气标签选择 | 可以保持原生 |
| 自定义 dropdown | 角色绑定选择 | 已经是自定义，可优化 |

## 8. 当前 UI 的问题清单

### 8.1 结构性问题

1. **所有组件写在 app.js 一个文件里**（2377 行），难以维护
2. **没有深色模式**，长时间使用眼睛疲劳
3. **CSS 1416 行写在一个文件**，没有变量化

### 8.2 布局问题

4. **资源条信息密度过高**，数字跳动时视觉干扰
5. **任务面板固定在底部**，占据宝贵垂直空间
6. **树形目录和详情面板宽度固定**（300px vs 1fr），不可调节
7. **工作台两栏宽度固定**（400px vs 1fr），不可调节

### 8.3 交互问题

8. **大量使用原生 `prompt()`/`confirm()`/`alert()`**，体验差且不可定制
9. **批量操作的范围选择不够直观**，用户容易搞混「整本/整卷/选中章节」
10. **角色绑定下拉用 `prompt()` 输入角色名**（批量绑定），容易输错
11. **「重新生成本块人声」实际是整章级别**，按钮文案有歧义
12. **试听「仅人声」按钮**没有"尚未生成"的置灰提示
13. **保存分块后不提示文本改动会导致语音作废**

### 8.4 信息展示问题

14. **角色库的引用统计**藏在卡片里，不容易一眼看到全局
15. **配置页过于简单**，没有分组折叠、没有说明文档链接
16. **任务日志查看器**是纯文本区域，没有高亮/过滤

### 8.5 重构方向建议

1. **组件拆分**：app.js → `pages/novels.js`, `pages/novel-detail.js`, `pages/workbench.js`, `pages/roles.js`, `pages/settings.js`
2. **CSS 变量化**：颜色、间距、圆角抽成 CSS 自定义属性，方便支持深色模式
3. **深色模式**：CSS 变量 + 顶部 toggle
4. **可调节布局**：面板间可拖拽分割线
5. **自定义弹窗组件**：替换所有 `prompt()`/`confirm()`/`alert()`
6. **更好的任务可视化**：进度条、耗时预估、日志查看器带语法高亮
7. **仪表盘首页**：汇总所有小说的进度概览（替代当前空空的小说列表首页）
8. **音频波形可视化**：试听时显示波形
9. **键盘快捷键**：提高操作效率（如上下箭头切换分块，空格试听）
10. **批量操作改用下拉选择**替代 `prompt()` 输入
