## 目标

在 005 的 REST API + SSE 之上写出完整可用的 Web 界面：全局资源监控条、
小说列表、小说详情（树形目录 + 批量任务 + 任务队列面板）、配音工作台、
全局角色库、系统配置页。

## 背景

被删掉的 Gradio 界面在这份规格上有四个硬伤：没有路由所以做不了页面记忆、
树形拖拽排序没有原生组件、配音工作台几百个分块卡片的多选列表会卡、
任务面板和资源条的实时刷新只能靠轮询。所以改用 FastAPI 后端 + 手写前端。

**前端不引入任何构建工具**。没有 npm、没有 webpack/vite、没有 `.vue` 单文件组件。
Vue 3 用浏览器全局版（`Vue.createApp`），组件用普通 JS 对象 + 模板字符串写。
这台机器是本地自用，不需要打包优化，构建链只会增加维护成本。

## 文件结构

```
web/static/
  index.html                 # 唯一的 HTML 入口
  vendor/
    vue.global.prod.js
    Sortable.min.js
  css/
    app.css
  js/
    app.js                   # 应用装配：路由、SSE、资源条、全局状态
    api.js                   # 所有 fetch 调用集中在这里，页面组件不直接写 fetch
    pages/
      novels.js
      novel-detail.js
      workbench.js
      roles.js
      settings.js
```

`index.html` 按顺序加载：vendor → `api.js` → 各个 `pages/*.js`（挂到 `window.Pages`）→ `app.js`。
不用 ES module 的 `import`，就用最朴素的全局变量挂载，避免跨浏览器的模块加载坑。

## 任务 1：骨架

### 1.1 vendor 文件本地化

**不要用 CDN 引用**——这是个离线优先的项目，界面不该依赖外网。一次性下载到本地：

```bash
mkdir -p web/static/vendor
curl -L -o web/static/vendor/vue.global.prod.js \
  https://cdnjs.cloudflare.com/ajax/libs/vue/3.5.13/vue.global.prod.min.js
curl -L -o web/static/vendor/Sortable.min.js \
  https://cdnjs.cloudflare.com/ajax/libs/Sortable/1.15.6/Sortable.min.js
```

下载后**检查文件大小和开头几行**，确认拿到的是真的 JS 而不是 404 页面。
版本号如果失效就去 cdnjs 找当前可用的版本，Vue 用 3.x 的 `global.prod` 构建，
Sortable 用 1.x 的 UMD 构建。

### 1.2 顶部常驻区（所有页面都在）

```
┌────────────────────────────────────────────────────────────────┐
│ novel2audiobook    [小说] [角色库] [设置]                       │
│ CPU 23%  内存 12.4/31.3G  GPU 87%  显存 18.2/24.0G  🔵TTS 占用  │
└────────────────────────────────────────────────────────────────┘
```

- 资源数据来自 SSE 的 `resource` 事件，不要自己起 setInterval 轮询。
- GPU 占用方（🟢LLM / 🔵TTS / ⚪空闲）来自 `GET /api/gpu/owner`，
  跟着 `resource` 事件一起刷新即可。
- 数字用等宽字体，**并且给每个数值留固定宽度**，否则每秒跳动会让整条抖动。

### 1.3 路由与页面记忆

用 hash 路由，五条：

```
#/novels                                    小说列表（默认）
#/novels/:novelId                           小说详情
#/novels/:novelId/chapters/:chapterId       配音工作台
#/roles                                     全局角色库
#/settings                                  系统配置
```

页面记忆：每次路由变化把当前 hash 写进 `localStorage['n2a.lastRoute']`；
应用启动时如果 URL 没带 hash，就跳到记住的那条（记录里的小说/章节已经不存在时
回落到 `#/novels`，**不要白屏**）。

### 1.4 SSE 客户端（`app.js`）

```js
// 连接 /api/events，把三类事件分发到全局响应式状态：
//   resource     -> state.resource
//   task_update  -> state.tasks（按 id 归并）
//   tree_update  -> 触发当前页面重新拉取树
// 降级：连续 3 次 onerror 就关掉 EventSource，改成每 3 秒轮询
//       GET /api/tasks 和 GET /api/monitor，并在顶栏显示「实时连接已断开」。
```

### 1.5 通用组件

- `<confirm-dialog>`：所有二次确认都用它。支持展示一段「影响面说明」文本
  （删除节点、重新导入正文、批量覆盖预检都要用）。
- `<toast>`：操作成功/失败提示，3 秒自动消失。
- 所有 API 报错都要弹 toast 显示后端返回的 `detail`，**不要静默吞掉**。

## 任务 3：小说详情页（`pages/novel-detail.js`）

这是最复杂的一页。三个区域：左侧树、右侧详情、底部任务面板。

### 3.1 树形目录

- 数据来自 `GET /api/novels/{nid}/tree`（一次请求就带回每章的状态，不要逐章再查）。
- 节点状态用色点标记：未解析（灰）/ 已解析（蓝）/ 已配音（绿）/ 陈旧（黄，
  后端返回的 status 里带 `STALE` 前缀的都算）。
- 节点操作：新增部 / 新增卷 / 新增章节 / 重命名 / 删除。
  可用的节点类型要跟着 `levels` 走——`levels.part` 为 false 时不显示「新增部」。
- **拖拽排序**用 SortableJS，每一层的 children 列表各初始化一个 Sortable 实例，
  `group` 设成同一个名字以支持跨层级拖动。拖完调
  `POST /api/novels/{nid}/nodes/reorder`，**失败要把 UI 回滚到拖动前的顺序**。
- 多选：章节节点支持 checkbox 多选，选中集合是批量任务的输入之一。

### 3.2 章节上传

选中一个部/卷作为父节点，上传 txt + 填章节名 → `POST /api/novels/{nid}/nodes`
建章节节点后 `PUT .../raw` 上传正文。
（Zip 批量导入是后续迭代功能，**本期不做**，界面上也不要留入口。）

### 3.3 批量任务

选择范围四选一：整本 / 整部 / 整卷 / 多选章节。前三种传 `node_id`，
最后一种传 `chapter_ids`——后端 `library.iter_chapters` 会统一展开。

三个批量动作：批量解析 / 批量生成人声 / 批量混音导出。

**每个动作的流程固定是两步**：

1. 先调 `POST /api/tasks/preflight`，把返回的汇总放进 `<confirm-dialog>`：
   > 本次涉及 12 章：新生成 8 章，3 章已有成品将被重新生成，1 章无需处理。
   > 预计 GPU 耗时：约 95 分钟。
   （`estimated_gpu_minutes` 为 null 时显示「未知（尚无历史数据）」，
   **不要自己编一个数字填上去**。）
2. 用户确认后才调 `POST /api/tasks` 真正提交。

### 3.4 任务队列面板

固定在页面底部，可折叠。

- 任务列表按 `group_id` 聚合：一行显示「批量 TTS · 第一卷 · 5/12 章完成」，
  展开后是每章一行。
- 每行显示进度条、状态、耗时；running 的行有取消按钮（`DELETE /api/tasks/{id}`）。
- 点任务行展开日志，`GET /api/tasks/{id}/log?offset=` 增量拉取，**只在展开时拉**，
  收起就停——不要给几十个任务同时拉日志。
- 数据来自 SSE 的 `task_update` 事件，不要轮询。

### 3.5 章节详情与重新导入

选中某章时右侧显示：总分块数、已配音块数、未配音块数、**未绑定角色块数**。

「重新导入章节文本」按钮：先调不带 `confirm` 的 `PUT .../raw` 拿到影响面，
弹窗明确写清后果：

> 重新导入会清空本章的剧本、时间线和成品 MP3。
> 已合成的 N 个语音片段会因为正文变化而失效（文件保留在 audio_cache 里，
> 但下次合成不会命中）。此操作不可撤销。

确认后带 `?confirm=1` 再调一次。

### 3.6 跳转工作台

选中章节后「进入配音工作台」→ `#/novels/:nid/chapters/:cid`。

## 任务 4：配音工作台（`pages/workbench.js`）

**上下文锁定**：这一页只服务于路由里的那一章，不提供切换其他小说的入口，
只有一个「返回小说详情」按钮。

### 4.1 顶部统计条

`总分块 121 · 已配音 87 · 未配音 34 · 未绑定角色 6`
未绑定角色数大于 0 时整个数字标红。

### 4.2 左侧分块列表

- 卡片显示：seg_id、文本前 40 字、绑定的角色名、状态点（已合成 / 未合成）。
- **`speaker` 为空的卡片整张标红**，并在角色位置显示「⚠ 未绑定」。
  这是 004 引入的新语义的落点——parse 时大模型只能从角色清单里选，
  选不到就留空，这些空缺需要人在这里补上。
- 长章节（100+ 分块）必须做虚拟滚动，只渲染可视区域附近的卡片。
  自己写一个简单的即可（固定行高 + `translateY` 偏移），不要为此引入库。
- 支持 checkbox 多选，支持「全选未绑定」快捷按钮。

### 4.3 右侧单块编辑

- 原文文本框，可编辑。
- 角色绑定下拉：数据来自 `GET /api/roles`，支持按分类筛选。
  **下拉底部必须有「＋ 新建角色并绑定」入口**——parse 不再自动注册角色之后，
  这是补齐缺失角色的唯一路径，没有它工作台就是死路。
  点了弹角色新建弹窗（名称/分类/性别），建完自动绑定到当前分块。
- 语气标签下拉：八个值，取自后端返回的枚举
  （neutral / happy / angry / sad / serious / afraid / surprised / calm）。
- **不要显示背景音/音效字段。** 当前 `mixing.voice_only` 为 true，
  效果音流水线还没打通，露出来只会让人误以为能用。
- 试听两种模式：
  - **仅人声**：直接用浏览器原生 `<audio>` 放
    `GET /api/novels/{nid}/chapters/{cid}/audio/{md5}.wav`，不经过后端合成。
  - **混音预览**：调后端合成后播放。
  - 该分块还没合成过时，「仅人声」按钮置灰并提示「尚未生成」。
- 「重新生成本块人声」按钮：文件已存在时弹一次覆盖确认。

保存改动调 `PATCH .../segments/{seg_id}`。**文本改动会让该块的 md5 变化，
原来的语音作废**，这一点要在保存时提示用户。

### 4.4 批量操作

多选后可以：批量绑定角色 / 批量修改语气 / 批量清空角色绑定
（`POST .../segments/batch`），以及批量生成人声 / 批量混音导出
（走 `POST /api/tasks`，同样先 preflight 再提交）。

**批量生成人声前要前端先拦一道**：选中的分块里还有未绑定角色的，直接弹错误
「选中的分块中有 N 个未绑定角色，请先指派」，不要提交上去让后端报错。
（后端 005 里也有这道校验，两边都要有——前端拦是为了体验，后端拦是为了正确性。）

## 给执行者的注意事项

- **不要引入构建工具**，不要 npm，不要 `.vue` 单文件组件。
- **不要用 CDN 引用**，vendor 文件必须本地化。

- **不要自己起 setInterval 轮询任务和资源**，走 SSE；轮询只是断线后的降级路径。

- **不要给几十个任务同时拉日志**，只有展开的那一个才拉。
- 界面文案用中文，与项目其余部分保持一致。

## review 发现的问题（已全部修复）

底层模块（`task_queue.py`/`gpu_arbiter.py`/`monitor.py`/`derived_index.py`/
`preflight.py`/`tts_engine.py` 切批逻辑）质量很高，尤其是"daemon 才切批、一次性
子进程整批下发"这条最容易出错的约束实现得很仔细。但 `src/api/routers/*.py`
这一层有 6 个可复现的实质性 bug，`tests/test_api.py` 当时只有 8 个用例、完全
没碰树操作/章节上传/分块编辑/任务提交/删除确认，所以全部漏网：

1. `POST /nodes` 建部/卷/章节点必现 500（新节点没生成 `id` 字段）
2. `POST /tasks`、`POST /tasks/preflight` 按"整本/整部/整卷"提交必现 500
   （把 `iter_chapters` 返回的字符串列表当字典处理）
3. `DELETE /nodes/{id}?confirm=true` 不会把受影响章节移入 `.trash/`，
   而是直接 `os.unlink` 删文件——与计划 004 里规定的"两步确认 + 移入回收站"语义不符
4. `PUT /chapters/{cid}/raw` 重新导入时，新正文会覆盖旧 `raw.txt` 但不会触发
   `import_chapter_raw`（后者负责清空剧本/时间线/成品 MP3），导致旧数据残留
5. `PATCH /config` 读取 `global_config.yaml` 后只改内存不写回磁盘
6. GPU 占用者标记（`gpu_arbiter._orphan_marker_path`）在 `__exit__` 时
   只删 marker 不恢复 llama-server——如果 `start_llama_server()` 抛异常，llama-server
   就永远停不下来

另外 `src/api/app.py` 里 `PROJECT_ROOT` 被 `from src.utils import PROJECT_ROOT`
冻结成 import-time 的绝对路径，导致所有 router 在单元测试（`chdir` 到临时目录）
里都找不到 `library_root`。修复方案：所有 router 改用 `resolve_path()` 在调用时
动态解析路径，不再依赖冻结常量。

测试用例从 8 个扩充到 29 个，覆盖上述全部 6 个 bug 路径。
